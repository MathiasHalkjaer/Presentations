01 · Description

A skill is a folder with a SKILL.md

Agent Skills is an open standard: the same folder works in any agent harness that supports it.

The folder · click a file 
.claude/skills/
  model-standards/
    
    references/
      
      
      
    scripts/
SKILL.md 
---
name: model-standards
description: Naming, display folder, description
  and DAX conventions for our Power BI semantic
  models. Use when creating, renaming, tidying,
  documenting or reviewing …
---
# Model standards
## Names
- Tables: singular business nouns, no prefixes
  (Customer, not DimCustomer).
- Columns and measures: words with spaces …
Always in contextThe name and description of every installed skill.
Loaded when usedEverything below the header.
The whole thing is text files and folders. The header has two lines that matter: the name, and the description. Everything under the header only loads when the agent decides to use the skill. In Claude Code, project skills live in .claude/skills, personal ones in your user folder.

01 · Description

How a skill is found

Progressive disclosure: the agent reads only as much as the task needs.

1Name and descriptionOf every skillAlways
2The rest of SKILL.mdThe instructionsWhen a request matches
3References and scriptsThe files SKILL.md points toOnly when the instructions say so

Matching is the agent's judgement, not a keyword search.

So write the words people type: rename, tidy, document, DAX.

Skills are chosen at the start of a conversation. Start a new one after you change a skill.

Three levels. Level 1 is cheap, so you can have many skills installed. Level 2 is the body of SKILL.md, loaded when the agent judges that the request matches the description. Level 3 is files the body points to, read only when needed. The consequence: the description is the most important line you write. It's the only part the agent sees when it decides.

01 · Description

The description decides

Same skill, same instructions. Only the description changes between the two runs.

Stage 1 · vague 
description: Helps with Power BI.

✕The skill doesn't load, or loads for the wrong reasons.

Stage 2 · sharp 
description: … Use when creating, renaming,
  tidying, documenting or reviewing …

✓Customer Key, Customer Name, Country, Segment. The table becomes Customer.

Same instructions, different description. That one line is the whole difference.

02 · References

References load only when they're needed

One line in SKILL.md, a whole style guide behind it.

SKILL.mdFor style and patterns, read references/dax-style.md.

Before 
IF([TotalSales]>50000,"High",
  IF([TotalSales]>20000,
    "Medium","Low"))
dax-style.md
After 
VAR CurrentSales = [Total Sales]
RETURN
    SWITCH(
        TRUE(),
        CurrentSales > 50000, "High",
        CurrentSales > 20000, "Medium",
        "Low"
    )

04 · Hooks

Hooks: rules the harness enforces

A hook is a script the harness runs by itself at a set moment. The agent doesn't choose it and can't skip it.

Before every call to the Power BI MCP server

Connect to Sales [Prod]The agent tries
no_production.pyMentions “Sales [Prod]”? Exit code 2.
✕ BlockedThe call never reaches Power BI

After every file edit

Adds measure total_returnsThe agent edits Sales.tmdl
check_names.py --hookProblems in that file? Exit code 2.
✓ Agent fixes itTotal Returns, with a description
Exit code 2 stops the action and shows the hook's message to the agent. Hooks live in .claude/settings.json: a feature of the harness, not of the skill standard.

05 · Sub-agents

Two ways to combine skills and sub-agents

Shown in Claude Code. Other harnesses do this differently, or not yet.

Give a sub-agent the skill

.claude/agents/table-documenter.md

---
name: table-documenter
tools: Read, Edit, Grep, Glob
skills: model-standards
---

Every sub-agent works to the same standard. The skill is the shared rulebook.

Run the skill as a sub-agent

.claude/skills/model-review/SKILL.md

---
name: model-review
description: …
context: fork
---

The skill's long work runs in its own context. Your conversation gets the result, not the reading.

Parallel helps with independent work, one table each. It multiplies mistakes with anything that touches the same files.

Open .claude/agents/table-documenter.md. The skills line is why all four worked to the same standard. The other direction: a skill that runs as a sub-agent, with context: fork in the header. Good for long reviews that would otherwise fill the main conversation.

06 · Learning loop

A skill that learns

At the end of each task the agent proposes what the skill was missing. You decide.

SKILL.md 
## After each task
List conventions you met that aren't
in this skill, and mistakes you corrected.
Propose each as an addition to the
right reference file, with one example.
Don't change this skill until I approve.

06 · Learning loop

The documentation writes itself

Every change to the skill is a commit you can review and roll back.

references/glossary.md

  | Business term | In the model      |
  | Net Sales     | excludes returns  |
+ | Category BIK  | Bikes             |
+ | Category ACC  | Accessories       |
+ | Category CLO  | Clothing          |

references/decisions.md

2026-11-03: Net Sales excludes
returned lines (Is Return = 1).
Agreed with finance, because their
monthly report shows sales after
returns.

The glossary feeds the descriptions. The decision log answers “why is it like this?” next year.

Show the glossary diff, then the commit. Also references/decisions.md, with the Net Sales decision and its reason. The skill reads decisions.md before deciding something the glossary doesn't cover. Keep the skill in git. Review before it changes itself.

Take it home

Three things to try yourself

1

Write one skill for your model standards

Spend most of the time on the description. Test it with requests that should, and shouldn't, load it.

2

Move one exact rule into a script

Then run it from a hook after every edit, so the agent can't forget.

3

Add “After each task”

Review what it proposes for a week. Keep what's true, reject the rest.

Three small steps, each one piece from today. Nobody needs all six pieces on day one.
